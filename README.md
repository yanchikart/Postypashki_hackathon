# Postupashki Marketing Measurement System (MMS)

Система сквозного учета маркетинга в Telegram, инкрементальной атрибуции заказов и оптимизации распределения рекламного бюджета для школы «Поступашки».

---

## 1. Назначение системы

Система решает три прикладные задачи:
1. **Сквозная идентификация (User Stitching):** Устранение потери атрибуции, вызванной тем, что 25–30% пользователей Telegram скрывают или не имеют публичного username. При переходе на сайт оплаты UTM-метки теряются, а в банковской выписке фиксируются только email или телефон без привязки к Telegram-аккаунту.
2. **Изоляция органического фона:** Разделение валовой выручки на естественный базовый спрос и чистый инкрементальный эффект от рекламных публикаций.
3. **Управление бюджетом:** Расчет оптимального сплита маркетингового бюджета на основе предельной окупаемости с защитой от каннибализации полной цены курсов.

---

## 2. Архитектура и поток данных

```text
[Пост в Telegram]
       │
       ▼ (клик по deep-link вида ?start=camp_pID)
[Telegram Mini App: Студент]
       │  - нативное считывание telegram_user_id
       │  - ввод email для получения материалов
       ▼
  [leads.csv]  <--- связка (telegram_id, email, post_id)
       │
       │ (детерминированный матчинг по email / user_id)
       ▼
 [orders.csv]  <--- банковские транзакции эквайринга
       │
       ▼
 [pipeline.py]
       │
       ├──> [marketing_measurement_system.xlsx] (витрины данных)
       ├──> [metrics.json]                      (расчетные агрегаты)
       │
       ▼
  [server.py]
       │
       ▼
[Telegram Mini App: Маркетолог]
  - Оптимизатор бюджета
  - Аналитический дашборд
```

Порядок обработки:
1. Пользователь переходит по ссылке с параметром кампании в Mini App. Клиентская часть считывает постоянный числовой идентификатор `telegram_user_id`.
2. При подтверждении формы регистрации создается запись в журнале лидов: связка `telegram_id`, `email`, `post_id` и метка времени.
3. Скрипт `pipeline.py` сопоставляет выписку эквайринга с журналом лидов в пределах заданного окна атрибуции, вычитает суточный органический фон, рассчитывает мультипликаторы эффективности и формирует витрины.
4. Веб-интерфейс отображает аналитику и рассчитывает распределение бюджета по запросу пользователя.

---

## 3. Разделение ролей в интерфейсе (Mini App)

Интерфейс приложения (`index.html`) адаптируется под роль пользователя через контекст Telegram WebApp API (`initDataUnsafe`):

### Режим студента (клиентский контур)
* Предназначен для сбора первичного контакта без нарушения конфиденциальности переписки.
* Пользователь указывает email для получения материалов разбора и активации условий.
* На экране подтверждения доступно единственное действие — переход в личные сообщения к менеджеру поддержки («Написать менеджеру по курсу в Telegram»).
* В фоновом режиме фиксируется связка Telegram ID с учетной записью на платформе.

### Режим маркетолога (аналитический контур)
Включает два рабочих экрана:
1. **Оптимизатор бюджета:** Интерактивный расчет сплита для введенного значения бюджета.
2. **Маркетинговая аналитика:**
   * График суточной выручки с отметками промо-кампаний относительно базовой линии органического фона.
   * Сводная таблица эффективности кампаний (`dm_campaigns_performance`): затраты, число заказов, средний чек, валовый ROMI и инкрементальный ROMI.
   * Структура выручки по категориям продуктов (бандлы, флагманы ПРО, линейка СТАРТ, специализации).
   * Сквозная конверсионная воронка от просмотров публикаций до подтвержденных оплат.

## 4. Регламент загрузки новых данных

Пайплайн поддерживает инкрементальное обновление данных без изменения кодовой базы.

Для загрузки свежих периодов:
1. Дополнить строки в исходных таблицах:
   * `orders.csv`: идентификатор заказа, идентификатор студента, временная метка, сумма, список курсов.
   * `posts.csv`: идентификатор публикации, временная метка, охват, реакции, идентификатор кампании, тип контента, канал.
   * `campaigns.csv`: реестр маркетинговых акций, даты начала и окончания.
2. Выполнить команду:
   ```bash
   python pipeline.py
   ```
3. Скрипт выполняет:
   * Группировку транзакций одного студента с совпадающим временем в бандлы.
   * Расчет атрибуции по модели Last Touch в окне 21 день.
   * Оценку базовой линии суточного органического фона.
   * Экспорт обновленных витрин в `marketing_measurement_system.xlsx` и структуры `metrics.json`.
   * Сервер `server.py` считывает новые коэффициенты без перезапуска процесса.

## 5. Методология предиктивного расчета

Расчет распределения бюджета основан на эмпирической отдаче каналов, очищенной от органического фона:

1. **Оценка базового фона (Holdout):**
   В данных зафиксирован период без акций и промо-активности (12–21 августа), определивший средний уровень органических продаж:
   $$Baseline = 54\,482.50	ext{ руб./день}$$
   Инкрементальная выручка кампании длительностью $D$ дней рассчитывается как:
   $$Revenue_{inc} = Revenue_{attr} - (D 	imes Baseline)$$

2. **Мультипликаторы отдачи:**
   Коэффициент предельной отдачи рассчитывается как отношение инкрементальной выручки к понесенным затратам:
   * BigTech стажировки: 17.77 (ROMI inc = +1677.5%)
   * Распродажа СТАРТ: 18.41 (ROMI inc = +1741.4%)
   * Флагманы ПРО и AI: 8.62 (ROMI inc = +762.2%)
   * Лид-магниты (NoSQL): 7.46 (ROMI inc = +645.8%)

3. **Логика распределения бюджета (Bounded Knapsack):**
   * **Ограничение на скидочные механики:** Кампания распродажи СТАРТ ограничена 15% общего бюджета (не более 60 000 руб.), чтобы избежать каннибализации спроса на флагманские курсы по полной стоимости.
   * **Масштабирование ядра:** Основная часть нераспределенного остатка направляется в кампанию BigTech благодаря максимальной отдаче без снижения цены.
   * **Поддержание среднего чека:** Второе по объему выделение направляется на продвижение флагманских линеек ПРО и AI (средний чек порядка 10 000 руб.).
   * **Воронка:** Фиксированные доли направляются на бесплатный лид-магнит (8%) и внешний тестовый посев (4%).

## 6. Маркировка данных (Data Provenance)

Данные в проекте строго разграничены:

* **Фактические данные (из кейса):**
  * `orders.csv` (628 заказов из `base.xlsx`): суммы, даты, состав покупок, объединенные в 153 бандла и 475 единичных оплат.
  * `posts.csv` (45 постов из `tg_posts_export.xlsx`): тексты, даты публикации, просмотры, реакции, пересылки.
  * `channels.csv` (9 каналов): перечень собственных медиашколы и внешних площадок.
* **Синтетические и реконструированные данные:**
  * **Затраты на рекламу (300 000 руб.):** В исходном файле `base.xlsx` отсутствовали данные о расходах. Суммы реконструированы на базе рыночной стоимости размещения в Telegram-каналах схожей тематики и охвата (CPV 1.5–2.5 руб.).
  * `leads.csv`: Журнал переходов сгенерирован для демонстрации работы 21-дневного окна атрибуции до интеграции с боевой базой бота (доля склейки 70%).

## 7. Инструкция по установке и запуску

### Запуск веб-интерфейса
Файл `index.html` работает автономно. Для просмотра достаточно открыть его в браузере. На панели доступен переключатель ролей («Студент» и «Маркетолог»).

### Запуск полного цикла с бэкендом
1. Клонировать репозиторий:
   ```bash
   git clone https://github.com/vooterr/postupashki-marketing-analytics.git
   cd postupashki-marketing-analytics
   ```
2. Установить зависимости:
   ```bash
   pip install pandas openpyxl
   ```
3. Запустить пересчет витрин:
   ```bash
   python pipeline.py
   ```
4. Запустить локальный сервер:
   ```bash
   python server.py
   ```
5. Открыть в браузере: `http://localhost:8000`
